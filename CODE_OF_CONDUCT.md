# Code of Conduct

Tinycast gets a lot of posts, comments and pull requests. Each one lands in someone's inbox, and each
one takes time to read. This page keeps the noise out, so real reports and good code get the
attention they deserve.

## The short version

**Don't create noise, and don't send work you don't understand.** Noise gets removed. Repeat
offenders get blocked.

## Notifications

Every comment, mention and cross-reference emails everyone who follows the post. Keep them for things
that matter.

- **No "+1", "me too" or "any update?" comments.** Click **"upvote"** or react with an emoji instead.
- **No needless @mentions.** Don't tag maintainers or other users to get attention, ask for a review
  or push for a reply. Every discussion and pull request is read.
- **Keep Tinycast's issue and PR numbers out of your fork.** A commit message, PR title or PR
  description on your fork with `#123`, `Fixes #123` or an @mention posts a "mentioned this" note on
  Tinycast's thread, **every time that commit lands in a branch, including each rebase, amend and
  force-push**. Put the reference only in the description of the pull request you open on Tinycast.
- **Don't push to an open pull request over and over.** Each push notifies everyone who follows it.
  Finish locally, then push.
- **Don't revive old or solved posts.** Start a new one and link the old one.

## Spam

- **Duplicates.** The same post again, or in more than one place. Search first.
- **Off-topic posts.** Anything not about Tinycast.
- **Self-promotion.** Links to your own app, product, channel or service.
- **Bots and mass posting.** Automated accounts, or the same content pushed across many posts.
- **Pressure.** Demanding features, deadlines or replies. Tinycast is free, and nobody owes anyone
  their time.

## AI usage

AI tools are welcome. Unchecked AI output is not. The problem is never the tool, it's sending work
that a human did not understand, check or stand behind.

- **Say when you used AI.** In a pull request, name the tool and how much of the work it did: wrote
  the code, wrote the tests, helped debug, or only autocomplete. "None" is a valid answer.
- **You must understand your code.** You must be able to explain every change, and how it fits the
  rest of the app, without help from AI. If you can't, don't send it.
- **Posts are written in your own words.** Issues, discussions, reviews and comments may use AI for
  research, but a human reads, checks and **edits** the text before posting. AI writing is wordy;
  trim it. Using a translator because English isn't your first language is fine.
- **No AI-generated media.** Images, icons, videos and audio come from a human or a real screen
  recording.
- **Check AI findings before you report them.** AI tools often invent bugs and security problems that
  don't exist. A made-up report, bug or vulnerability gets an instant **block**.
- **Answer review comments yourself.** Don't paste a reviewer's comment into an AI tool and paste the
  reply back.

## Code quality

- **Start with a discussion.** A pull request is not the place to design a feature. Ask first through
  a [Vouch Request](https://github.com/abue-ammar/tinycast/discussions/new?category=vouch-request), and
  wait for a yes.
- **Meet the bar in [CONTRIBUTING.md](CONTRIBUTING.md).** Tests, lint and a clean build pass locally.
  Memory stays under budget. No leaks.
- **Use the app with your change in it.** Code that compiles but was never run is not ready.
- **No throwaway pull requests.** Typo-only PRs made just to show up as a contributor, PRs nobody
  asked for, or code the author didn't test.
- **Read your own diff before you open the PR.** Most review comments are things a second pass would
  have caught.

## Where this applies

**Issues, discussions, pull requests, reviews, and commits that reference Tinycast**, including
commits on forks.

## What happens

1. **The post gets marked as spam, hidden or deleted. The pull request gets closed.**
2. **A warning**, when it looks like an honest mistake.
3. **A block** from the repository.

Bots, self-promotion, mass posting, made-up reports and repeated AI slop skip straight to a
**block**.

## How to report

Use GitHub's **Report content** option on the post.
